🧰 “Safe lanes” to start (low-risk wins)

  • 📝 Docs, meeting notes, summaries, RFC drafts
  • 🧪 Unit tests + test refactors (with running tests)
  • 🧹 Code cleanup: renames, formatting, lint fixes
  • 🧩 UI scaffolding & quick prototypes (behind feature flags)

🛡️ “High-risk” lanes to slow down

  • 🔐 Security-sensitive code, auth, cryptography, input validation
  • 🧾 Legal/IP, customer data, regulated domains (health/finance)
  • 🧨 Infra changes with blast radius (prod config, IAM, networking)
If you must use AI in high-risk lanes, do it with tighter verification gates + human review + strong logging/auditing.

🧾 Shareable “team norms” starter pack

🧑‍⚖️ Minimum rules (lightweight)

  • 🧷 Label AI usage in PRs / docs when it materially influenced output.
  • 🧪 Run verification: tests, build, lint, and quick threat-check for risky areas.
  • 🧼 Small diffs beat giant “AI refactor bombs”.
  • 🔐 No secrets in prompts. Treat prompts as potentially logged.

🧠 Best prompt add-on (works everywhere)

Append this to most prompts to reduce “Prompt Hero” failure modes:
Before you answer:
1) List assumptions you made.
2) List what could be wrong / unsafe.
3) Give a quick verification plan (tests, checks, sources).
4) If uncertain, say so and propose safer options.
